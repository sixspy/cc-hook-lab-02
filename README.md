## 主链

**端点登记 → 事件入队 → 签名投递 → 失败重试与死信 → 投递账互证**

页面：投递台 · 端点名册 · 事件队列 · 投递流水 · 死信匣 · 签名规 · 投递互证 · 事件详情

> 题材声明：Webhook 投递控制台。**不是**工单客服 / OA / CRM / 预约 / 电商订单（官方雷同禁区）。**不是**数据工程采集入库。

## hook-02 并发投递互斥

- 工程形态（择定）：**独立队列按事件号占投递坑并拒绝重复回刷**；双写两轨不采用，`双写归档轨` 维持空桩。
- 同事件投递先占 `投递锁` 坑位，占坑写入与尝试写入、事件命运更新同事务同成同败；第二路会话拿到 HTTP 409，正式 `投递尝试` 集合不产生第二张票。
- 坑态词表：占用中 / 已释放（失败让坑供重试）/ 终票占坑（已投递、死信，永久拒回刷）；死信重投回收坑位。
- 中文命运可读：待投 / 投递中 / 已投递 / 死信；投递台、事件队列、投递流水、签名规四页与事件详情卡均展示事件号、占坑态、尝试行数、中文命运。
- 互证新增双票异常对账（只读跨表联查，不落影子表、不混正式集合），同事件多成功票判不对齐。
- 并发联调脚本：`python3 -I backend/scripts/双会话并发打锁.py`，双会话同事件并发应得一成一拒（200/409）。
- 测试：`tests/test_hook_race_1.py`（双成功票）、`test_hook_race_2.py`（对账双票）、`test_hook_race_3.py`（占坑态与回刷），三红分服务救绿。
